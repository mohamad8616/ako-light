# URL-Based Locale Routing Plan

## Goal

Add locale-prefixed URLs (`/fa/about`) while keeping English unprefixed at root (`/about`). Language detection via middleware (cookie + `Accept-Language` header). Data localization is explicitly **out of scope** for this phase.

## Current State

- Next.js 16, App Router, 17 page routes under `app/`
- Custom `LanguageProvider` (React Context + `localStorage`) drives `useLanguage()`
- Language switcher calls `setLang()` — changes state but not URL
- All `<Link href>` values are hardcoded without locale
- No `middleware.ts` exists
- `next.config.ts` has no i18n config
- RTL handled via `dir` attribute toggled in `LanguageProvider`

## Architecture Decisions

| Decision | Choice |
|----------|--------|
| Default locale URL | English unprefixed (`/about`), Persian prefixed (`/fa/about`) |
| Route structure | `[locale]` dynamic segment wrapping all routes |
| Locale resolution | URL `params.locale` → React Context (single source of truth) |
| Detection priority | 1. URL prefix, 2. Cookie (`henge-lang`), 3. `Accept-Language` header |
| Library | None — continue using existing `LanguageProvider` |

## Implementation Steps

### 1. Create `middleware.ts` at project root

- Define supported locales: `["en", "fa"]`, default: `"en"`
- On incoming request:
  - Check if URL starts with `/fa` → locale is `fa`
  - If no locale prefix → check cookie `henge-lang`, then `Accept-Language` header
  - If detected locale is `fa` and URL has no prefix → redirect to `/fa${pathname}`
  - If detected locale is `en` or no preference → serve from root (no redirect needed)
- Add `locale` to response cookies so subsequent visits persist
- Use `NextResponse.rewrite` to keep internal routing clean (URL shows `/fa/about`, Next.js serves from `[locale]/about`)
- Matcher should exclude `_next`, `api`, static files

### 2. Restructure `app/` to include `[locale]` segment

Move all existing routes into `app/[locale]/`:

```
app/[locale]/page.tsx              ← formerly app/page.tsx
app/[locale]/about/page.tsx        ← formerly app/about/page.tsx
app/[locale]/collections/page.tsx
app/[locale]/collections/[slug]/page.tsx
... (all 17 routes)
app/[locale]/layout.tsx            ← moves from app/layout.tsx
app/[locale]/not-found.tsx
```

The root `app/layout.tsx` becomes a thin redirect (or is removed entirely if middleware handles it).

### 3. Update root layout (`app/[locale]/layout.tsx`)

- Accept `params: { locale: string }` and validate it's a supported locale
- Pass `locale` to `LanguageProvider` as initial/default value
- Set `<html lang={locale} dir={dir}>` statically (SSR-friendly, no hydration mismatch)
- Generate localized metadata using `generateStaticParams` and `generateMetadata`
- Add `hreflang` alternate links (`en` + `fa`) in `<head>` for SEO

### 4. Refactor `LanguageProvider` to sync with URL

- Accept `initialLocale` prop from layout params
- On mount, if context locale ≠ URL locale, update to match URL (URL is source of truth)
- Keep `localStorage` as fallback for non-URL scenarios (direct component usage)
- `setLang()` should now use `router.push()` to navigate to the other locale's URL instead of just updating state — **or** keep `setLang` for in-page toggles and add a separate `navigateToLang()` that updates the URL
- Read `dir` from locale (fa → rtl, everything else → ltr)

### 5. Update language switcher (`MenuBtns.tsx`)

- Replace `setLang("en")` / `setLang("fa")` with navigation that respects current path
- On toggle: use `usePathname()` + `useRouter()` to construct target URL
  - Currently `en` (root) → navigate to `/fa${pathname}`
  - Currently `fa` (`/fa/...`) → navigate to pathname without `/fa` prefix
- This ensures the URL updates when switching language

### 6. Make all `<Link>` components locale-aware

Create a locale-aware link helper. Two options:
- **Option A**: Wrap `next/link` in a `LocalizedLink` component that prefixes `href` with `/fa` when locale is `fa`
- **Option B**: Export a `useLocalizedPath()` hook returning `(path) => string` and wrap each `href`

Files with hardcoded links that need updating:
- `components/footer/footer.tsx` (/, /credits, /privacy)
- `components/footer/newsLetterSection.tsx` (/terms)
- `components/navbar/Navbar.tsx` (/)
- `components/home/HomeCarousel.tsx` (/hlife)
- `components/home/HomeCollectionBanner.tsx` (/collection)
- `components/home/HengeParisBanner.tsx` (/hlife/henge-paris)
- `components/home/HengeLondonBanner.tsx` (/showroom/showroom-henge-london)
- `components/ui/HeroSectionText.tsx` (/catalogue)
- `components/ui/ProductsSheet.tsx` (/products)
- `components/flagship/flag/FlagshipInfoSection.tsx` (/showroom)
- `components/designers/designer/DesignerHeader.tsx` (/designers)
- `components/collections/collection/AboutCollection.tsx` (/collections)
- `components/products/prod/ProdInfoSection.tsx` (/products)
- `app/not-found.tsx` (/)

### 7. Add `generateStaticParams` to static pages

For SSG pages with `[locale]` segment, export:
```ts
export function generateStaticParams() {
  return [{ locale: "en" }, { locale: "fa" }];
}
```

Apply to: all static pages (homepage, about, catalogue, collections, designers, flagship, materials, projects, s34, contact, products).

### 8. Localized metadata

Update `layout.tsx` to use `generateMetadata` that returns localized `title`, `description`, and `alternates.languages` for hreflang tags.

## Validation Plan

1. `npm run build` — must succeed with `[locale]` segment
2. Manual routes check:
   - `/` → serves English homepage
   - `/fa` → serves Persian homepage
   - `/about` → English about page
   - `/fa/about` → Persian about page (URL is `/fa/about`)
   - `/collections/some-slug` → works in both locales
3. Language switcher: clicking `فارسی` on `/about` navigates to `/fa/about`
4. Middleware: visiting `/fa` with `en` cookie stays at `/fa` (URL is source of truth)
5. Middleware: visiting `/` with `fa` cookie redirects to `/fa`
6. `npm run lint` — passes
7. No hydration warnings in console (SSR `lang`/`dir` matches client)

## Out of Scope (Future Phases)

- Data layer localization (using `Localized` type / `pick()`)
- RTL Tailwind class audit (logical properties)
- Server-side translation loading
- Number/date/pluralization formatting
- Additional languages beyond `en` + `fa`

## Risks / Notes

- **Hydration**: Setting `<html lang dir>` server-side from `params.locale` avoids mismatch. `suppressHydrationWarning` on `<body>` is already present.
- **Existing bookmarks**: English links (e.g. `/about`) continue to work. Only Persian users get redirected to `/fa/...`.
- **SEO**: Add `hreflang` tags in metadata. Submit separate sitemaps per locale when content goes live.
- **Route restructuring**: Moving 17 files into `[locale]` is mechanical but touches every page. Consider doing it as one commit.
