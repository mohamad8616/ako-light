# Fix invisible images in `/flagship` (and other list routes)

## Root cause

`components/ui/Row.tsx:51` builds Tailwind class names inside a template literal:

```tsx
className={`h-${height} w-${width} ... lg:w-${pathname === "materials" || pathname === "projects" ? "90" : "60"}`}
```

Tailwind JIT only generates CSS for classes it can see as **literal** strings in source files. Because these are inside template literals, the scanner never sees them, so no CSS is emitted.

Effects by breakpoint:

| Breakpoint | Classes used | Result |
|---|---|---|
| Base (<640px) | `h-30` / `w-30` (or `w-40` on materials) | **Container is 0×0** → images invisible |
| sm (640px) | `sm:h-56` `sm:w-56` | Visible — 224×224 |
| md (768px) | `md:h-72` `md:w-72` | Visible — 288×288 |
| lg (1024px) | `lg:h-60` `lg:w-60` (or `lg:w-90`) | **Ignored** → falls back to `sm:w-56` (224px) |

Additional issues:
- `30` is not in Tailwind's default spacing scale, so `h-30`/`w-30` would be invalid even if JIT could see them.
- `90` is also not in the default spacing scale, so `lg:w-90` is invalid on the materials/projects branch.

## Data flow

- `FlagshipList`, `DesignersList`, `CollectionsList` do **not** pass `height`/`width` → defaults `"30"`/`"30"`.
- `MaterialsList` and `ProjectList` pass `width={"40"}` → `w-40` is a valid Tailwind class but still dynamic, so it is **not** generated by JIT either.

## Fix

Replace the dynamic class construction in `Row.tsx` with **literal** class strings so the scanner can emit CSS.

1. **Base mobile size**: use arbitrary-value Tailwind classes that match the intended pixel values derived from the `30` / `40` props (`30 × 0.25rem = 7.5rem`, `40 × 0.25rem = 10rem`).
2. **lg width**: use a literal ternary with two valid class strings — `lg:w-60` for flagship/designers/collections, and `lg:w-[22.5rem]` for materials/projects (`90 × 0.25rem = 22.5rem`, since `90` is not in the default scale).
3. Keep the existing responsive `sm:`/`md:` literal classes unchanged.

### Target file

- `components/ui/Row.tsx` — line 51 className

### Implementation outline

```tsx
const heightClass = "h-[7.5rem]";            // 30 × 0.25rem = 120px
const widthClass = width === "40"
  ? "w-[10rem]"                              // 40 × 0.25rem = 160px
  : "w-[7.5rem]";                            // 30 × 0.25rem = 120px
const lgWidthClass = route === "materials" || route === "projects"
  ? "lg:w-[22.5rem]"                         // 90 × 0.25rem = 360px
  : "lg:w-60";                               // 15rem = 240px

<div
  className={`${heightClass} ${widthClass} shrink-0 overflow-hidden sm:h-56 sm:w-56 md:h-72 md:w-72 lg:h-60 ${lgWidthClass}`}
  ...
>
```

## Validation

1. Run the app and visit `/flagship` on mobile viewport — images should render with a 120×120 container.
2. Visit `/materials` and `/projects` on mobile — images should render with a 120×160 container.
3. Visit `/flagship` on lg breakpoint — images should be 240×240 (not stuck at 224×224).
4. Visit `/materials` and `/projects` on lg breakpoint — images should be 240×360.
5. Confirm no `h-30`/`w-30`/`lg:w-90` classes remain in source.
